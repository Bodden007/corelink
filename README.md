
# CoreLink

## Архитектурный устав разработки

**Проект:** `Bodden007/corelink`\
**Назначение:** защищённое native-ядро промышленной HMI\
**Клиент:** Avalonia / .NET 10\
**Язык ядра:** Rust\
**Первый промышленный протокол:** Modbus TCP

> CoreLink должен оставаться настолько простым, насколько позволяет
> реальная задача, но не проще требований безопасности, надёжности и
> детерминированности.

# 1. Назначение

CoreLink --- небольшое, понятное и детерминированное Rust-ядро,
являющееся единственным владельцем коммуникации с PLC.

CoreLink отвечает за:

-   получение конфигурации через FFI;
-   валидацию конфигурации;
-   проверку HWID и Ed25519;
-   владение Modbus TCP соединением;
-   polling PLC;
-   декодирование данных;
-   хранение последнего подтверждённого состояния;
-   выполнение записи;
-   timeout;
-   reconnect;
-   корректный lifecycle.

CoreLink не содержит предметной логики установки.

Он не знает:

-   насос;
-   давление;
-   температуру;
-   SCFM;
-   HT400;
-   азот.

Для CoreLink существуют только:

``` text
Parameter ID
Register Area
Address
Data Type
Word Order
Value
Quality
```

# 4. Правило mod.rs

`mod.rs` является картой модуля, а не местом хранения реализации.

Допустимо:

``` rust
pub mod state;
pub mod core;
```

Запрещено размещать в `mod.rs`:

-   бизнес-логику;
-   алгоритмы;
-   обработку данных;
-   lifecycle;
-   большие реализации.

Пример:

``` text
core
├── mod.rs       # состав модуля
├── core.rs      # реализация CoreLink
└── state.rs     # состояния
```

Главное правило:

> mod.rs показывает архитектуру модуля, но не реализует её.

# 5. Граница .NET ↔ Rust

.NET отвечает за:

-   UI;
-   ViewModel;
-   Rx;
-   формирование конфигурации;
-   команды оператора;
-   отображение результата.

Rust отвечает за:

-   безопасность;
-   Modbus;
-   polling;
-   timeout;
-   reconnect;
-   декодирование;
-   snapshot;
-   запись.

Схема:

``` text
Avalonia / .NET

        |
        | FFI
        |
        v

     CoreLink

        |
        | Modbus TCP
        |
        v

       PLC
```

# 6. Modbus коммуникация

На один CoreLink существует один владелец Modbus соединения.

Только он:

-   открывает соединение;
-   выполняет Read;
-   выполняет Write;
-   делает reconnect;
-   закрывает соединение.

Read и Write не выполняются параллельно.

Запись получает приоритет перед следующим Poll.

------------------------------------------------------------------------

# 7. Snapshot

CoreLink хранит последнее успешно полученное состояние.

Минимальный snapshot:

``` text
Sequence
Timestamp
Quality
Values
```

История значений не хранится без отдельного требования.

.NET получает последнее состояние, а не историю каждого Poll.

# 8. Ошибки и надёжность

Все ожидаемые ошибки обрабатываются через:

``` rust
Result<T, E>
```

В production-path запрещены:

``` rust
panic!
unwrap()
expect()
```

Ошибки связи являются штатными состояниями:

``` text
Connected
Disconnected
Timeout
Faulted
```

# 9. Правила разработки

## Public API

`pub` используется только при реальной необходимости.

## Trait

Trait создаётся только если:

-   есть несколько реализаций;
-   нужна реальная подмена;
-   существует архитектурная граница.

## Unsafe

Основная логика --- safe Rust.

`unsafe` допускается только на минимальной FFI-границе.

## Оптимизация

Порядок:

``` text
Correct
   ↓
Readable
   ↓
Measured
   ↓
Optimized
```

Не выполнять преждевременную оптимизацию.
